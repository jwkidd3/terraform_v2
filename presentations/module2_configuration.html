🗄️ State Management Concepts

State (terraform.tfstate) maps every resource address in your configuration to a real object ID in AWS. Terraform reads it on every plan - treat it as critical data.

# Inspect state
terraform state list                         # List all resource addresses
terraform state show aws_s3_bucket.demo      # Show one resource's attributes
terraform state show 'aws_s3_object.demo_files[0]'   # Quote count/for_each addresses
terraform graph | head -20                   # Dependency graph (DOT format)

# Change state (not infrastructure)
terraform state rm aws_instance.old          # Forget a resource - it stays in AWS
terraform state mv aws_instance.a aws_instance.b  # Rename an address

# Manual backup before risky operations - use a distinct name:
# Terraform itself overwrites terraform.tfstate.backup on every write
cp terraform.tfstate terraform.tfstate.manual-backup

✅ State Best Practices

  • Back up before manual state operations
  • Use unique, username-prefixed resource names
  • State can contain secrets - protect it
  • Never commit *.tfstate - add it to .gitignore

🏢 Team Storage Options

  • HCP Terraform (Day 3)
  • S3 backend with native locking (use_lockfile = true)
  • Other remote backends (azurerm, gcs, consul)

🔄 Drift, Import & State Locking

🔍 Detecting Drift

# Update state from real infrastructure, then compare
terraform plan -refresh-only     # Preview what changed outside Terraform
terraform apply -refresh-only    # Accept those changes into state
# (terraform refresh = apply -refresh-only -auto-approve)
terraform plan                   # Any remaining diff = drift

📥 Bringing Resources Back Under Management

# CLI import: address + provider-specific ID
# (an S3 object's import ID is <bucket name>/<key>)
terraform import 'aws_s3_object.demo_files[2]' \
  $(terraform output -raw bucket_name)/demo/file-3.txt
# Config-driven import block (Terraform >= 1.5)
# Reviewed in terraform plan, applied with terraform apply
import {
  to = aws_s3_object.demo_files[2]
  id = "user1-state-demo-bucket-a1b2c3d4/demo/file-3.txt"
}

🔒 State Locking

Locking stops two runs from writing the same state at once. The local backend locks the state file automatically; remote backends need a lock mechanism.

terraform {
  backend "s3" {
    bucket       = "my-team-tf-state"
    key          = "app/terraform.tfstate"
    region       = "us-east-2"
    use_lockfile = true # S3 native locking (Terraform >= 1.11)
  }
}

💡 Note: S3 native locking is GA in Terraform 1.11, which also deprecates DynamoDB-based locking (dynamodb_table). It is not available on the class's Terraform 1.9.8 - the labs use local state. A stuck lock can be cleared with terraform force-unlock LOCK_ID - only when you are sure no run is active.

📦 Module Recap: What Modules Give You

Modules are containers for multiple resources that are used together. They enable you to create reusable components and organize your Terraform code.

Benefits:

  • Reusability: Use the same module across environments
  • Organization: Logical grouping of resources
  • Abstraction: Hide complexity behind clean interfaces
  • Consistency: Standardize infrastructure patterns
  • Testing: Test modules independently

module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "~> 5.0" # any 5.x release

  name            = "${local.name_prefix}-vpc"
  cidr            = "10.0.0.0/16"
  azs             = local.azs
  private_subnets = ["10.0.1.0/24", "10.0.2.0/24"]
  public_subnets  = ["10.0.101.0/24", "10.0.102.0/24"]

  enable_nat_gateway = true
  single_nat_gateway = true # one NAT keeps cost down
}

# Submodule of the security-group module
module "web_security_group" {
  source  = "terraform-aws-modules/security-group/aws//modules/http-80"
  version = "~> 5.0"

  name                = "${local.name_prefix}-web-sg"
  vpc_id              = module.vpc.vpc_id # module output as input
  ingress_cidr_blocks = ["0.0.0.0/0"]
}

module "s3_logs" {
  source  = "terraform-aws-modules/s3-bucket/aws"
  version = "~> 3.0"

  bucket        = "${local.name_prefix}-app-logs-${random_string.bucket_suffix.result}"
  force_destroy = true
}

🔗 Wiring Modules Together

  • Outputs such as module.vpc.vpc_id and module.vpc.public_subnets feed other modules and resources
  • Read each module's Inputs and Outputs tabs on registry.terraform.io
  • //modules/http-80 selects a submodule inside the package

📥 Registry Workflow

  • terraform init downloads modules into .terraform/modules
  • Module resources appear in state with a prefix, e.g. module.vpc.aws_vpc.this[0]
  • Changing a version constraint requires terraform init -upgrade

💡 Versioning: ~> 5.0 allows any 5.x but never 6.0 - major versions can rename inputs and outputs.

🏗️ Advanced Variable Patterns

Enterprise Reality: Modern infrastructure requires complex, validated configurations that scale across multiple environments and teams.

🔍 Complex Type Validation

Environment Configuration with Advanced Validation
variable "environments" {
  description = "Multi-environment infrastructure configuration"
  type = map(object({
    # Compute Configuration
    instance_type = string
    min_size      = number
    max_size      = number

    # Feature Flags
    enable_logging    = bool
    enable_backup     = bool
    enable_monitoring = bool

    # Security Configuration
    allowed_cidrs   = list(string)
    security_groups = list(string)

    # Cost Control
    max_monthly_cost = number
  }))

  validation {
    condition = alltrue([
      for env, config in var.environments :
      can(regex("^t[2-4]\\.(nano|micro|small|medium)", config.instance_type))
    ])
    error_message = "Instance types must be cost-effective t2, t3, or t4 family (nano through medium)."
  }

  validation {
    condition = alltrue([
      for env, config in var.environments :
      config.min_size <= config.max_size && config.max_size <= 10
    ])
    error_message = "Min size must be <= max size, and max size must be <= 10 for cost control."
  }

  validation {
    condition = alltrue([
      for env, config in var.environments :
      config.max_monthly_cost > 0 && config.max_monthly_cost <= 10000
    ])
    error_message = "Monthly cost limit must be between $1 and $10,000."
  }
}

💡 Pro Tip: Layer multiple validation rules to catch different types of configuration errors early in the development cycle.

⚡ Dynamic Configuration with Locals

Enterprise Pattern: Use locals to create computed values that adapt to different environments while maintaining consistency.

Advanced Locals Configuration
locals {
  # Environment-specific configuration
  env_config = var.environments[var.current_environment]

  # Computed naming patterns
  resource_prefix = "${var.organization}-${var.project_name}-${var.current_environment}"
  instance_name   = "${local.resource_prefix}-web"

  # Conditional logic for different environments
  monitoring_enabled = var.current_environment == "production" ? true : local.env_config.enable_monitoring
  backup_enabled     = contains(["production", "staging"], var.current_environment)

  # Data transformation: a CIDR pair per availability zone
  az_distribution = {
    for i, az in data.aws_availability_zones.available.names :
    az => {
      private_subnet = cidrsubnet(var.vpc_cidr, 8, i + 10)
      public_subnet  = cidrsubnet(var.vpc_cidr, 8, i + 20)
    }
  }

  # Consistent tagging strategy - static values only
  common_tags = merge(var.default_tags, {
    Environment    = var.current_environment
    Project        = var.project_name
    ManagedBy      = "Terraform"
    ConfigVersion  = var.config_version # e.g. "2024.06", set per release
    BackupEnabled  = tostring(local.backup_enabled)
    MonitoringTier = local.monitoring_enabled ? "enhanced" : "basic"
  })
}

🎯 Best Practice: Use locals to eliminate code duplication and create single sources of truth for computed values.

⚠️ Avoid timestamp() in tags: it returns a new value on every run, so every plan shows changes on every tagged resource. Use a static value - or, if you must, add lifecycle { ignore_changes = [tags["DeployedAt"]] }.

📈 Variable Precedence & Source Management

Key Rule: When the same variable is set in several places, the source higher in this list wins.

🔍 Precedence Order (Highest → Lowest)

  1. -var and -var-file on the command line - processed in the order given; the later one wins
  2. *.auto.tfvars / *.auto.tfvars.json - loaded in lexical (alphabetical) order
  3. terraform.tfvars.json
  4. terraform.tfvars
  5. Environment variables TF_VAR_*
  6. Variable defaults in the variable block

🧪 Why the labs keep username out of terraform.tfvars: any tfvars file outranks TF_VAR_username, so a value there would silently override the username you exported.

🎯 Strategic Usage

  • Defaults: Safe fallbacks
  • terraform.tfvars: Values shared by every environment
  • -var-file: Per-environment values
  • TF_VAR_*: Per-user values and secrets
  • -var: One-off overrides

🛠️ Multi-Environment Variable Strategy (Lab 8)

One codebase, one tfvars file per environment
environments/
├── dev.tfvars
├── staging.tfvars
└── prod.tfvars

# environments/dev.tfvars
environment    = "dev"
instance_type  = "t3.micro"
instance_count = 1

# environments/prod.tfvars
environment    = "prod"
instance_type  = "t3.medium"
instance_count = 3

# Choose the environment explicitly on every run
export TF_VAR_username="user1"   # per-user value
terraform plan  -var-file=environments/dev.tfvars
terraform apply -var-file=environments/dev.tfvars

# Preview another environment without applying
terraform plan  -var-file=environments/prod.tfvars

⚠️ Don't name them dev.auto.tfvars and prod.auto.tfvars: every *.auto.tfvars file loads automatically in lexical order, so prod would silently win over dev.

⚡ Dynamic Blocks: Flexible Resource Configuration

Pattern: A dynamic block generates repeated or optional nested blocks inside a resource. Lab 8 uses this for environment-specific security rules and spot instances.

Security Group with Environment-Driven Rules
resource "aws_security_group" "application" {
  name_prefix = "${var.project_name}-${var.environment}-app-"
  vpc_id      = var.vpc_id
  description = "Application security group with dynamic rules"

  # One ingress block per element of var.ingress_rules
  dynamic "ingress" {
    for_each = var.ingress_rules
    content {
      description = "${ingress.value.description} (${var.environment})"
      from_port   = ingress.value.from_port
      to_port     = ingress.value.to_port
      protocol    = ingress.value.protocol

      # Wrap a multi-line conditional in parentheses
      cidr_blocks = (
        var.environment == "production"
        ? ingress.value.prod_cidrs
        : ingress.value.dev_cidrs
      )
    }
  }

  # Different egress rule sets per environment
  dynamic "egress" {
    for_each = var.environment == "production" ? var.prod_egress_rules : var.dev_egress_rules
    content {
      description = egress.value.description
      from_port   = egress.value.from_port
      to_port     = egress.value.to_port
      protocol    = egress.value.protocol
      cidr_blocks = egress.value.cidr_blocks
    }
  }

  tags = merge(local.common_tags, {
    Name = "${var.project_name}-${var.environment}-application-sg"
  })
}

⚡ Dynamic Blocks: Optional and Generated Blocks

Launch Template (Lab 8 Pattern)
resource "aws_launch_template" "app" {
  name_prefix   = "${var.project_name}-app-"
  image_id      = data.aws_ami.amazon_linux.id
  instance_type = var.instance_type

  # Optional block: present only when spot is enabled
  dynamic "instance_market_options" {
    for_each = var.cost_optimization.use_spot_instances ? [1] : []
    content {
      market_type = "spot"
      spot_options {
        max_price = var.cost_optimization.max_price
      }
    }
  }

  # Generated blocks: one per extra EBS volume
  dynamic "block_device_mappings" {
    for_each = var.additional_ebs_volumes
    content {
      device_name = block_device_mappings.key
      ebs {
        volume_size = block_device_mappings.value.size
        volume_type = "gp3"
        encrypted   = true
      }
    }
  }

  # Tag everything the template launches
  dynamic "tag_specifications" {
    for_each = ["instance", "volume"]
    content {
      resource_type = tag_specifications.value
      tags          = local.common_tags
    }
  }
}

🚀 Dynamic Block Toolkit

  • for_each = cond ? [1] : [] - include a block 0 or 1 times
  • Iterate a map: .key and .value on the iterator
  • Iterator name defaults to the block label
  • Whole resources: count = var.enable_high_availability ? 1 : 0 (Lab 8's ALB)

💡 Best Practices

  • Use for optional or repeated nested blocks
  • Prefer static blocks when the shape never changes
  • Keep iterator names descriptive
  • Plan with every environment's tfvars file

🔗 Section 4: Dependencies, Lifecycle & VPC Networking

Resource orchestration, lifecycle management, and 2-tier network design

🔗 Implicit Dependencies

Dependency Graph: Terraform builds a graph from resource references and creates independent resources in parallel. Every reference is an implicit dependency.

Automatic Dependency Chain
# VPC created first
resource "aws_vpc" "main" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
  enable_dns_support   = true
}

# Internet Gateway depends on VPC
resource "aws_internet_gateway" "main" {
  vpc_id = aws_vpc.main.id # creates dependency
}

# Subnet depends on VPC
resource "aws_subnet" "public" {
  vpc_id                  = aws_vpc.main.id
  cidr_block              = "10.0.1.0/24"
  availability_zone       = data.aws_availability_zones.available.names[0]
  map_public_ip_on_launch = true
}

# Route table depends on VPC and IGW
resource "aws_route_table" "public" {
  vpc_id = aws_vpc.main.id

  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.main.id
  }
}

⚡ How It Works

  • Referencing aws_vpc.main.id tells Terraform the VPC must exist first
  • Creation follows the graph; destruction runs in reverse
  • Visualize it with terraform graph (Lab 6)
  • Prefer implicit dependencies - they document themselves

🎯 Explicit Dependencies with depends_on

Manual Control: Use depends_on only when a dependency exists that Terraform cannot see in your references.

Hidden Dependencies Made Explicit
# NAT gateway needs a working IGW, but never references it
resource "aws_nat_gateway" "main" {
  allocation_id = aws_eip.nat.id
  subnet_id     = aws_subnet.public[0].id

  depends_on = [aws_internet_gateway.main]
}

# Instance bootstraps from S3 - IAM policy must exist first
resource "aws_instance" "web" {
  ami                    = data.aws_ami.amazon_linux.id
  instance_type          = var.instance_type
  subnet_id              = aws_subnet.private[0].id
  vpc_security_group_ids = [aws_security_group.web.id]
  iam_instance_profile   = aws_iam_instance_profile.web.name

  user_data = <<-EOF
    #!/bin/bash
    aws s3 cp s3://${aws_s3_bucket.app_data.id}/bootstrap.sh /tmp/
    bash /tmp/bootstrap.sh
  EOF

  depends_on = [
    aws_iam_role_policy.s3_access,       # permissions ready
    aws_route_table_association.private, # outbound route via NAT
  ]
}

🔍 When to Use Explicit Dependencies

  • IAM Permissions: Policies attached before a resource uses them
  • Network Readiness: Routes and gateways ready before instances boot (Lab 9)
  • Side Effects: Scripts that call AWS APIs at boot

⚠️ Caution: Overusing depends_on makes plans more conservative and slower - don't add it where a reference already exists.

🛡️ Lifecycle: Protecting Critical Resources

Production Reality: Lifecycle rules prevent downtime, data loss, and noisy plans.

Critical Resource Protection
resource "aws_db_instance" "production" {
  identifier     = "${var.project_name}-prod-db"
  engine         = "postgres"
  engine_version = "16"
  instance_class = "db.t3.large"

  allocated_storage     = 100
  max_allocated_storage = 1000
  storage_encrypted     = true

  db_name  = var.database_name
  username = var.database_username
  password = var.database_password

  backup_retention_period   = 30
  skip_final_snapshot       = false
  final_snapshot_identifier = "${var.project_name}-prod-db-final"

  lifecycle {
    # Critical: refuse any plan that would destroy this
    prevent_destroy = true

    # Password is rotated outside Terraform
    ignore_changes = [password]
  }
}

⚠️ Lifecycle Best Practices

  • prevent_destroy: Databases, state stores, critical data
  • create_before_destroy: Load-balanced services and DNS records
  • ignore_changes: Use sparingly - it can hide real drift
  • replace_triggered_by: Replace when a referenced resource changes

💡 Tip: Avoid timestamp() in arguments like final_snapshot_identifier - it changes every run and causes a permanent diff.

🔄 Lifecycle: Zero-Downtime Updates

Replace the Template When the App Version Changes
# replace_triggered_by accepts resource references only,
# so wrap the variable in a terraform_data resource
resource "terraform_data" "app_version" {
  input = var.app_version
}

resource "aws_launch_template" "web" {

  instance_type = var.instance_type

  vpc_security_group_ids = [aws_security_group.web.id]

  user_data = base64encode(templatefile("${path.module}/userdata.sh", {
    app_version = var.app_version

    create_before_destroy = true

  name                      = "${var.project_name}-web-asg"
  vpc_zone_identifier       = aws_subnet.private[*].id
  target_group_arns         = [aws_lb_target_group.web.arn]

🔁 For_Each: Named Resources

Best for: Resources identified by a name - addresses stay stable when an item is removed.

Security Groups and Rules Keyed by Name
variable "security_rules" {
  type = map(object({
    description = string
    port        = number
    cidr_blocks = optional(list(string), [])
    source_sg   = optional(string) # key into aws_security_group.this
  }))

    web_http  = { description = "HTTP from ALB", port = 80, source_sg = "alb" }

}

resource "aws_security_group" "this" {
  for_each = toset(["alb", "web"])

  name   = "${var.project_name}-${each.key}"
  vpc_id = aws_vpc.main.id
}

resource "aws_security_group_rule" "web_ingress" {
  for_each = var.security_rules

  type              = "ingress"
  security_group_id = aws_security_group.this["web"].id
  description       = each.value.description
  from_port         = each.value.port
  to_port           = each.value.port
  protocol          = "tcp"

  # Exactly one source: another security group OR CIDR blocks
  source_security_group_id = each.value.source_sg != null ? aws_security_group.this[each.value.source_sg].id : null
  cidr_blocks              = each.value.source_sg == null ? each.value.cidr_blocks : null
}

✅ Custom Conditions & Data Persistence

Guard Rails: precondition and postcondition blocks live inside lifecycle and fail the run with a clear message.

Lifecycle Rules in Practice

resource "aws_instance" "critical_server" {
  ami           = data.aws_ami.amazon_linux.id
  instance_type = var.instance_type

  lifecycle {
    prevent_destroy       = true
    create_before_destroy = true
    ignore_changes        = [ami, user_data]

    # Replace when the security group is replaced
    replace_triggered_by = [aws_security_group.web.id]

    # Checked before the change is planned
    precondition {
      condition     = can(regex("^t[23]\\.", var.instance_type))
      error_message = "Instance must be T2 or T3 family."
    }

    # Checked after the resource is created/updated
    postcondition {
      condition     = self.instance_state == "running"
      error_message = "Instance failed to start properly."
    }
  }
}

Targeted Operations

Resource Replacement Strategies

# Force replacement of a resource (preview first)

🌐 2-Tier VPC Building Blocks (Lab 9)

🏗️ The Architecture

  • Public subnets (2 AZs): ALB and the NAT Gateway; route 0.0.0.0/0 → Internet Gateway
  • Private subnets (2 AZs): EC2 web servers; route 0.0.0.0/0 → NAT Gateway
  • Single NAT Gateway with an Elastic IP - lower cost, one AZ of egress
  • Route table associations attach each subnet to its route table

🔒 Security Group Chaining

  • ALB SG: HTTP/HTTPS from 0.0.0.0/0
  • Web SG: HTTP only from the ALB SG (security_groups = [aws_security_group.alb.id])
  • Web servers have no public IPs
Private Egress via a Single NAT Gateway
resource "aws_eip" "nat" {

}

  allocation_id = aws_eip.nat.id
  subnet_id     = aws_subnet.public[0].id # NAT lives in a public subnet
  depends_on    = [aws_internet_gateway.main]
}

resource "aws_route_table" "private" {

    cidr_block     = "0.0.0.0/0"
